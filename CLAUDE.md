# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Project Is

**Hale Servis Takip Sistemi** is a Progressive Web App (PWA) for Hale Mobilya's furniture service tracking. It allows staff to create, track, and manage furniture service requests, spare parts orders, and technician assignments across multiple store branches.

## Architecture Overview

This is a **zero-build, single-file frontend** application. There is no package manager, no bundler, and no framework.

```
index.html    — Entire application: HTML markup, embedded CSS (~800 lines), embedded JS (~2300 lines)
sw.js         — Service Worker for PWA offline caching
manifest.json — PWA manifest (standalone display mode)
assets/       — Partner logos (Bellona, Mondihome) used in print forms
icons/        — PWA icons (16px–512px)
```

**There is no build step.** Open `index.html` directly in a browser or serve it from any static file server to run the app.

## Backend: Google Apps Script

All data is stored in **Google Sheets**, accessed via a deployed Apps Script Web App. The `API_URL` constant near the top of the `<script>` block points to this endpoint:

```js
const API_URL = 'https://script.google.com/macros/s/.../exec';
```

Every read/write goes through `apiCall(action, data)`, which POSTs JSON with the shape `{ token, action, data }`. When updating the backend URL, change only `API_URL`. The auth token is persisted in `localStorage` under the key `hale_auth_token`.

### API actions

| Action | Purpose |
|---|---|
| `login` / `logout` | Session management |
| `changePassword` / `resetPassword` | Password ops |
| `load` | Fetch all records + settings + current user |
| `addRecord` / `updateRecord` / `deleteRecord` | Service record CRUD |
| `saveSettings` | Persist statuses/branches/priorities/montors/salesPersons |
| `nextOrderNo` | Get next auto-incremented service number from the server |
| `addUser` / `updateUser` / `deleteUser` / `listUsers` | User management (admin only) |
| `getLoginLogs` | Audit log (admin only) |

The server returns `{ ok: true, ... }` on success or `{ ok: false, error, code }` on failure. The special error codes `NO_AUTH` (triggers re-login) and `NO_PERMISSION` (shows a toast) are handled globally in `apiCall()`.

## Frontend State & Rendering

All application state lives in a single global `state` object:

```js
const state = {
  records: [],      // All service records loaded from server
  products: [],     // Product catalog (currently unused/empty)
  settings: { statuses, branches, priorities, montors, salesPersons },
  newItems: [],     // Service line items staged for the "New Service" form
  editItems: [],    // Service line items staged in the edit modal
  editItemIndex: null  // Which item is currently being edited in the modal
};
```

The `DB` object is the only interface to the backend. After any mutation (`DB.addRecord`, `DB.updateRecord`, `DB.deleteRecord`, `DB.saveSettings`), call `renderAll()` to refresh the UI.

**Auto-refresh**: `startAutoRefresh()` polls `DB.refresh(true)` every 15 seconds, but skips polling when the edit modal is open to avoid clobbering in-progress edits.

## Data Model

A **record** is a service request. Key fields:

- `id` — generated by `makeId('SRV')`
- `items[]` — array of service line items (each with `id`, `productName`, `productCode`, `materialCode`, `lotNo`, `fioriNo`, `problem`, `completed`, `completedAt`)
- `montors` — comma-separated string of technician names
- `openClosed` — derived: `'Açık'` or `'Kapalı'` (set by `isClosedStatus(status)`)
- `history[]` — audit trail of status changes

Legacy records may have top-level `productName`/`productCode`/`materialCode`/`problem` instead of `items[]`. **Always use `getRecordItems(record)`** to read items — it handles both old and new formats, and `syncLegacyFields()` normalizes records on load.

### Service number format

`HL{yy}{mm}SER{BRANCH_CODE}{12-digit-sequence}` — e.g. `HL2505SERTLS000000000001`

Branch codes: `OPT` (Optimall), `TLS` (Talas), `MON` (Mondi). The sequence resets each month. In multi-user mode, the server generates the final number (returned in `res.orderNo` from `addRecord`).

## Role-Based Access Control

Four roles: `admin > manager > user > readonly`. Permissions are enforced with CSS class toggles injected by `applyRolePermissions()`:

| CSS class | Visible to |
|---|---|
| `.role-write` | user, manager, admin |
| `.role-manager-up` | manager, admin |
| `.role-admin` | admin only |

The `user` role additionally has `.work-orders-field` (İş Emirleri textarea) hidden via CSS.

## Key Conventions

**Turkish character handling**: Use `upperTr(str)` (not `.toUpperCase()`) wherever text must be uppercased, because standard JS `.toUpperCase()` converts `i→I` instead of `i→İ`.

**HTML safety**: All user-supplied content rendered into innerHTML must be wrapped with `esc(s)` for HTML escaping and `escAttr(s)` for attribute values.

**Phone numbers**: Stored and displayed as `+90 5xx xxx xx xx`. Use `normalizePhoneDisplay()` to format for display and `normalizePhoneForWhatsapp()` to strip to digits for `wa.me/` URLs.

**Branch names**: Always normalize via `normalizeBranchName()` before storing. The canonical values are `'OPTIMALL MAĞAZA'`, `'TALAS MAĞAZA'`, `'MONDI MAĞAZA'`.

**Dates**: Input/storage uses `YYYY-MM-DD`. Display uses `formatDate()` → `DD.MM.YYYY`. For `<input type="date">` population, use `toDateInputValue()` which strips any leading `'` (Google Sheets text marker) and the `T...Z` timezone suffix.

**Closed status detection**: Use `isClosedStatus(status)` — a record is closed if its status string contains `'tamamlandı'`, `'iade'`, or `'iptal'`.

## Developing in This Codebase

Since everything is in one `index.html` file, there is no lint or test command. To verify changes:

```bash
# Serve locally (any static server works)
python3 -m http.server 8080
# Then open http://localhost:8080 in a browser
```

The app requires a valid `API_URL` pointing to a deployed Apps Script backend. Without it, `boot()` will show an alert and halt. For UI-only work, you can temporarily stub `apiCall` to return mock data.

When editing, search for sections using the comment headers in the JS block:
- `// ============= UZAK BACKEND` — DB/API layer
- `// ============= KULLANICI YÖNETIMI` — User management functions
- `// ============= AUTH FONKSİYONLARI` — Login/logout/password
- `// ============= ROL TABANLI YETKILENDIRME` — RBAC
- `/* ---------- Summary helpers ---------- */` — Dashboard stats
- `/* ---------- Utility ---------- */` — Generic helpers (esc, makeId, formatDate, etc.)

## Print Feature

`printServiceForm(id, selectedItemIds)` generates an A4 HTML receipt injected into `#printArea` and triggers `window.print()`. When a record has multiple items, it first opens a selection modal so the user can choose which items are being delivered now vs. deferred to a future visit. Deferred items show a "sonraki servis ziyaretinde teslim edilecektir" notice on the print form. The print form embeds all three brand logos (Hale, Bellona, Mondihome) as `<img src="data:...">` or `assets/*.png`.
